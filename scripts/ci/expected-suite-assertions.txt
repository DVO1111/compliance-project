# Expected assertion counts per SQL suite.
#
#  WHAT THIS CATCHES THAT THE ZERO-ASSERTION CHECK DOES NOT.
#  --------------------------------------------------------
#  The runner already fails a suite that reports 0/0, which is what an
#  abort BEFORE the summary looks like. Three things it could not see:
#
#    1. A suite that loses assertions without losing all of them. A
#       section that stops running — an early RETURN, a fixture that no
#       longer matches, a DO block that silently does nothing — still
#       prints a summary and still passes. The count falls and nobody
#       notices.
#    2. A suite FILE that disappears. The runner globs the directory, so
#       a deleted or renamed suite is simply not run, and the summary is
#       green because nothing failed.
#    3. The aggregate quietly drifting down over several changes.
#
#  So each suite declares a FLOOR: the number of assertions it had when
#  this line was written. Fewer is a failure. More is fine and expected —
#  tests get added — and the line is updated when that happens.
#
#  Updating a floor downward is a deliberate act that shows up in review,
#  which is the point. If a suite legitimately sheds assertions, lower
#  the number in the same commit that removes them and say why.
#
#  Regenerate the whole file after a run with:
#      scripts/ci/run-sql-tests.sh --write-expected
#
#  Format: <suite filename> <minimum assertions>
#  TOTAL is the aggregate floor across every suite.
